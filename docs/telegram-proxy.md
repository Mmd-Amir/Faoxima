# اتصال تلگرام از طریق پراکسی

از پنل وب فاکسیما، با حساب ادمین اصلی، به «تنظیمات متفرقه ← اتصال تلگرام» بروید. آدرس یک پراکسی قابل‌دسترسی از میزبان فاکسیما را وارد کنید.  مثال برای پراکسی Xray محلی:

```text
socks5h://127.0.0.1:1070
```

`socks5h` نام میزبان تلگرام را در سمت پراکسی حل می‌کند. `socks5` از DNS سرور فاکسیما استفاده می‌کند. پراکسی‌های HTTP CONNECT و HTTPS نیز پشتیبانی می‌شوند. آدرس باید پورت داشته باشد. در صورت نیاز credentials را در قالب `scheme://user:password@host:port` وارد کنید و نویسه‌های رزروشده در نام کاربری یا گذرواژه را percent-encode کنید. آدرس کامل در دیتابیس برنامه ذخیره می‌شود و پنل آن را دوباره نمایش نمی‌دهد. دسترسی دیتابیس و فایل‌های پشتیبان آن را محدود کنید.

پس از ذخیره، «آزمون پراکسی ذخیره‌شده» با `getMe` اتصال همان ربات را آزمایش می‌کند. فعال‌کردن پراکسی به‌تنهایی روی ارسال از Bot API و دانلود فایل‌های ربات اصلی اثر دارد. حالت پیش‌فرض دریافت وب‌هوک است. راه‌اندازها و ربات‌های فرعی `vpnbot` چرخهٔ نصب و دریافت خودشان را دارند.

## مهاجرت از وب‌هوک یا ریلهٔ قبلی

1. فاکسیما را با PHP CLI هم‌نسخهٔ PHP برنامه و با افزونه‌های cURL و PDO MySQL اجرا کنید. پردازشگر از `proc_open` استفاده می‌کند. هر دو فرایند باید با کاربر کم‌دسترسی برنامه و همان تنظیمات و دسترسی دیتابیس PHP-FPM اجرا شوند. در نصب برنامه با ربکا، مسیر و کاربر همان پوشهٔ برنامه در ربکا هستند. در کانتینر، پراکسی باید از شبکهٔ کانتینر قابل‌دسترسی باشد.
2. برای آزمایش از یک ربات جدا و سپس برای مهاجرت از یک بازهٔ کم‌ترافیک استفاده کنید. پراکسی را در پنل امتحان کنید. ریلهٔ قدیمی و هر فرایند دیگری که برای همان توکن `getUpdates` می‌زند متوقف کنید. حالت لانگ‌پولینگ را در پنل ذخیره کنید. این کار وب‌هوک فاکسیما را در برنامه موقتاً متوقف می‌کند.
3. دستور زیر را با کاربر برنامه، از پوشهٔ فاکسیما اجرا کنید. صف تلگرام هنگام جداکردن وب‌هوک حفظ می‌شود. حلقهٔ polling خودش وب‌هوک را حذف نمی‌کند. خطای 409 ممکن است از وب‌هوک یا دریافت‌کنندهٔ دیگری باشد.

   ```sh
   php scripts/telegram-polling.php detach-webhook
   ```

4. فایل نمونهٔ [سرویس systemd](faoxima-telegram@.service) را با نام `faoxima-telegram@.service` در `/etc/systemd/system/` قرار دهید. مسیر و `FAOXIMA_USER` را متناسب با نصب تغییر دهید. سپس هر دو واحد را راه‌اندازی کنید. برای نصب بدون systemd، همان فرمان‌های PHP با آرگومان‌های `poll` و `work` را تحت سرپرستی سرویس اجرا کنید.

   ```sh
   sudo systemctl daemon-reload
   sudo systemctl enable --now faoxima-telegram@poll.service faoxima-telegram@work.service
   journalctl -u faoxima-telegram@poll.service -u faoxima-telegram@work.service -f
   ```

5. وضعیت اتصال و صف را از پنل بررسی کنید. `/start`، یک دکمه، یک عملیات وابسته به ربکا و ارسال یا دریافت یک فایل را با ربات آزمایشی اجرا کنید. تنظیمات فایروال ریلهٔ قدیمی را بعد از تأیید مسیر جدید و بررسی سرویس‌های دیگر بازبینی کنید. نیازی به باز کردن پورت ورودی برای تماس Telegram Bot API نیست.

## رفتار هنگام قطعی و راه بازیابی

- دریافت‌کننده پیش از ارسال آفست بعدی کل دسته را در InnoDB ثبت می‌کند. پردازشگر جداست و برای هر کاربر ترتیب آپدیت‌ها را رعایت می‌کند. پس از راه‌اندازی مجدد، دریافت تکراری در صف به همان شناسه متصل می‌شود. در حالت عادی، payload پس از پایان پردازش پاک می‌شود و شناسه برای جلوگیری از تحویل تکراری تا دو روز می‌ماند.
- هنگام قطعی، آپدیت‌های ثبت‌شده در دیتابیس می‌مانند و دریافت‌کننده با تأخیر افزایشی دوباره تلاش می‌کند. تلگرام آپدیت‌های دریافت‌نشده را حداکثر ۲۴ ساعت نگه می‌دارد. با قطع کامل مسیر ایران تا پراکسی، پاسخ بلادرنگ ممکن نیست. برای دوام در برابر خرابی دیسک، دیتابیس را نیز باید پشتیبان گرفت.
- بعد از توقف ناگهانی پردازشگر یا پاسخ نامشخص در درخواست خروجی حین پردازش، ردیف به «نیازمند بررسی» می‌رود. پیام‌های بعدی همان کاربر منتظر می‌مانند و پیام‌های کاربران دیگر قابل پردازش‌اند. اثر عملیات را در فاکسیما، ربکا و تلگرام بررسی کنید. اگر تکرار امن است `retry` را اجرا کنید. اگر عملیات انجام شده و ردیف باید بسته شود، `resolve` را اجرا کنید؛ بستن ردیف محتوای آن را پاک می‌کند. از شمارهٔ ردیف نمایش‌داده‌شده در پنل استفاده کنید.

  ```sh
  php scripts/telegram-polling.php retry ROW
  php scripts/telegram-polling.php resolve ROW
  ```

- این صف برای آپدیت‌های ورودی است. فراخوانی‌های خروجی فاکسیما همچنان همگام‌اند. Bot API برای `sendMessage` کلید idempotency ارائه نمی‌کند. اگر ارتباط پس از ارسال قطع شود، تکرار خودکار ممکن است پاسخ یا عملیات را دوباره اجرا کند.
- بعد از تغییر توکن در `config.php`، هر دو واحد را دوباره راه‌اندازی کنید. تعویض توکن همان ربات صف آن را حفظ می‌کند. صف ربات اصلی با یک bot ID دیگر جداست.

برای برگشت به وب‌هوک، ابتدا صف محلی را بررسی و تخلیه کنید، دو واحد را متوقف کنید و لانگ‌پولینگ را از پنل غیرفعال کنید. سپس `php scripts/telegram-polling.php attach-webhook` را با کاربر برنامه اجرا کنید. تنظیم وب‌هوک هم آپدیت‌های منتظر در تلگرام را نگه می‌دارد.

## اجرای آزمون رگرسیون

روی یک دیتابیس خالی مخصوص آزمون، با PHP CLI و افزونه‌های cURL و PDO MySQL اجرا کنید:

```sh
TELEGRAM_TEST_DSN='mysql:host=localhost;dbname=faoxima_test' TELEGRAM_TEST_USER='tester' php scripts/tests/telegram-inbox.php
```
