# فاکتور کیوب‌پی داخل ربات

وقتی نمایش کارت داخل ربات در تنظیمات فروشنده فعال باشد، شماره کارت و مبلغ دقیق قابل پرداخت در یک پیام نمایش داده می‌شوند. مبلغ به هر دو واحد تومان و ریال، با برچسب هشدار و قالب قابل کپی نشان داده می‌شود؛ برای نمونه:

- ⚠️ مبلغ دقیق به تومان: `52,157`
- ⚠️ مبلغ دقیق به ریال: `521,570`

اگر فروشنده هر دو روش را فعال کرده باشد و پاسخ کیوب‌پی شامل لینک مخصوص کریپتو باشد، دکمهٔ «💎 پرداخت با کریپتو» به همین پیام متصل می‌شود. لینک اصلی پرداخت هم باقی می‌ماند. مبلغ پایهٔ سفارش جداگانه کنار مبلغ دقیق کارت نمایش داده نمی‌شود تا با مبلغ شامل آفست اشتباه نشود.

## پیش‌نیاز سمت کیوب‌پی

برای نمایش هم‌زمان کارت و دکمهٔ کریپتو، API کیوب‌پی باید قابلیت اختیاری زیر را پشتیبانی کند. تغییر سمت فاکسیما به‌تنهایی اطلاعات کارت را به پاسخ قدیمیِ انتخاب روش اضافه نمی‌کند.

درخواست ساخت سفارشِ مسیر تلگرام، علاوه بر داده‌های قبلی، `inline_card: true` می‌فرستد. سایر فراخوان‌های API و مینی‌اپ همان رفتار قبلی را دارند. پاسخ کارت می‌تواند دو فیلد اضافه داشته باشد:

| فیلد | کاربرد |
| --- | --- |
| `pay_amount_rial` | مبلغ دقیق ریالی همان فاکتور، شامل آفست؛ بر مقدار قدیمی تومان اولویت دارد. |
| `crypto_payment_url` | لینک HTTPS مربوط به همین سفارش در دامنهٔ `cubevps.ir` برای انتخاب کریپتو. |

فاکسیما از روی لینک صفحهٔ انتخاب روش، لینک کریپتو حدس نمی‌زند و فاکتور دوم ایجاد نمی‌کند. سرور کیوب‌پی باید هنگام تغییر روش، پرداخت‌شدن کارت را کنترل کند و تنها فاکتور کارتیِ پرداخت‌نشدهٔ همان سفارش را لغو کند. پس از واریز بانکی نباید روش پرداخت تغییر داده شود.

در پاسخ قدیمیِ کارت، ریال از تومان محاسبه می‌شود؛ در پاسخ انتخاب روش یا کریپتوی تنها، لینک صفحهٔ پرداخت حفظ می‌شود. اگر نمایش کارت غیرفعال باشد، شماره کارت در پیام قرار نمی‌گیرد. مبلغ ریالی نامعتبر به مبلغ گرد‌شده تبدیل نمی‌شود.
